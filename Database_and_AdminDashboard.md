## Database Setup

By default, Django uses SQLite. The settings.py file can be used to manage database configurations among other settings.

The INSTALLED_APPS contains the following default apps:

1. django.contrib.admin - the admin site
2. django.contrib.auth - an authentication system.
3. django.contrib.contenttypes - framework for content types.
4. django.contrib.sessions - a session framework.
5. django.contrib.messages - a messaging framework.
6. django.contrib.staticfiles - framework for managing static files




Some of these application make use of at least one database table, though so, a database is needed before they can be used.

` python manage.py migrate `

The command creates a database based on the settings.py file.

### Creating Models

A model is a single, definitive source of info about data. It contains the essential fields and behaviours of the data being stored.

In the polls app, there're two models: Questions and Choice. A question has a question and a publication date while a Choice has two fields: the text of the choice and a vote tally. Each choice is then associated with a Question.

```
from django.db import models


class Question(models.Model):
    q_text = models.CharField(max_length=200)
    pub_date = models.DateTimeField("date published") #human readable name for the field

class Choice(models.Model):
    q = models.ForeignKey(Question, on_delete=models.CASCADE)
    choice = models.CharField(max_length=200)
    votes = models.IntegerField(default=0)
```
The above code in Polls/models.py gives the model for the database in the pollsApp.

First, the models module  is imported from django.db

Every class defined is a subclass of models.Model and each of them has a number of variable that represent a databse field in the mode.

The first positional argument of the Field() specifies the human readable name. It is optional. The variable itself  is the machine-readable and will be used by Django to create the fields name and across python.

### Activating Models

The model code give Django the ability to:

- Create a database schema for the app
- Create a Python database-access API for accessing Question and Choice objects. 



But first, the project needs the polls app to be installed.

>> Django apps are "pluggable", meaning a single app can be used in multiple projects and it's possible to distibute apps, because they don't have to be tired to a given Django installation.

To 'plug' the app into the project, it needs to be included in the INSTALLED_APPS list like this:
` polls.apps.PollsConfig `

The pollsConfig class is in the polls/apps.py file.

Now, running the command: 
`python manage.py makemigrations polls ` will tell Django that there are some new changes. However to 'commit' the changes to the database, the command `python manage.py migrate`is used instead; so it's basically a two step process.
